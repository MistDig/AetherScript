# AetherScript AI reference

## Current capabilities

This document describes the shipped engine. It supports native .aether message commands, typed positional arguments, immutable and mutable locals, bounded loops, typed functions, immutable homogeneous lists, arithmetic, boolean conditions, explicit reload, revisions and rollback. Events, inventories, item grants, economy, quests and script-level persistent player variables are planned. Do not invent syntax or promise unsupported gameplay.

Use tool discovery from the connected app as the authority for available tools. Hosted and local gateways expose different tools. A hosted service version may differ from the plugin release version.

## Tools by connection mode

Hosted OAuth MCP exposes exactly these six tools:
- aether_server_status {}
- aether_scripts_list {}
- aether_scripts_read {id}
- aether_scripts_validate {id, source}
- aether_scripts_apply {id, source, expectedHash}
- aether_scripts_test {id, expectedMessages, arguments?}

The local stdio gateway additionally has aether_capabilities {}, aether_validate {source, format}, and aether_test {source, format, expectedMessages, arguments?}. Offline and loopback status modes have four tools total, including aether_server_status, and cannot deploy. A local gateway using a management relay profile has nine tools. Hosted clients cannot call aether_capabilities, aether_validate or aether_test. Use the hosted script tools instead.

format is aether, yaml or json for local validation/testing. Remote management uses native .aether files. arguments is an optional list of strings, including strings for integer and boolean inputs. expectedMessages is an ordered list of exact message strings.

## Permissions and autonomous edits

Read aether_server_status and aether_scripts_list. The live status includes allScripts and targets.
When allScripts is true, you may create any valid native feature ID and edit existing native scripts within the user's request. An empty list of existing scripts does not remove permission to create one.
When allScripts is false, use only the granted IDs. Explain the need for fresh owner approval if the requested ID is outside that grant.
Choose a sensible ID when the user authorizes creation but supplies no name. Do not ask for an additional approval already granted by the user and server. Never claim a denied operation succeeded.
Feature IDs are lowercase, start with a letter, and contain only lowercase letters, digits and hyphens, up to 64 characters. The source filename must match the ID. Full native access does not overwrite existing YAML/JSON sources or bypass source-format collisions.

## Safe editing workflow

1. Read the target with aether_scripts_read.
2. For creation, confirm exists=false and use expectedHash "ABSENT". For edits use the returned hash.
3. Write a complete valid native source. Keep explicit permission and sender rules.
4. Validate with aether_scripts_validate, then apply with aether_scripts_apply.
5. Read back source, hash and activeHash. Confirm the intended source is active.
6. Test using aether_scripts_test with explicit expectedMessages and arguments.
7. Report actualMessages, matched and the active revision. A synthetic test does not certify player rendering or player-only behavior.

On a stale source hash, read again before merging. After a timeout or unknown network outcome, read back before retrying because the change may already be committed. Invalid edits preserve the working revision. A test mismatch is not success.

## Complete runnable example

Save as greet.aether. Paper registers the real command name from the header. Direct server-console dispatch, replacement and restart are tested. /ais run greet remains available; connected-player command-tree visibility has not yet been verified.

```aether
feature greet version "1.0.0"
command greet permission "aetherscript.example.greet" sender any {
  arg name: text
  arg excited: boolean = true
  if excited {
    send "Hello " + name + "!"
  } else {
    send "Hello " + name
  }
}
```

Test the active feature with:
{"id":"greet","arguments":["MistDig"],"expectedMessages":["Hello MistDig!"]}
Then test:
{"id":"greet","arguments":["Alex","false"],"expectedMessages":["Hello Alex"]}
A player invokes /ais run greet "Alex Smith". Administrator console commands omit the leading slash.

## Syntax and limits

Declare arg name: text, arg count: integer = 1 or arg enabled: boolean = true at the start of a command. Required arguments precede defaults. At most 16 arguments, each at most 2048 UTF-16 units. Integer inputs are signed 64-bit decimal strings; booleans are exactly true or false. Quoted console arguments can contain spaces.

let creates an immutable inferred scalar or homogeneous list value. if requires a boolean. send requires text. Use text(value) for explicit scalar conversion; lists cannot be converted directly. Operators include +, -, *, /, %, comparisons, equality, !, && and ||. Braces delimit blocks; put statements on separate lines. Comments begin //.
Commands with arguments, var/set, loops or function declarations evaluate with fresh local state per invocation. Legacy scripts using only let, if and send without arguments preserve preparation-time evaluation and semantic hashes. Both branches are type-checked. Arithmetic errors, budget failures and invalid arguments fail before messages are emitted.
Source limit is 64 KiB locally. The hosted tool's source schema allows at most 16000 characters and its serialized request has a smaller transport envelope than the compiler's source limit. Keep remote scripts comfortably within both limits.
Messages are plain text, at most 2048 UTF-16 units each and at most 32 emitted messages per invocation. Conditional or zero-iteration paths may emit none. No arbitrary host objects, Java calls or general console execution.


## Mutable locals, loops and functions

var count = 3 declares an inferred mutable local. set count = count - 1 updates the nearest visible mutable binding with the same type. let, arguments and function parameters remain immutable. Locals support text, integer, boolean and homogeneous lists; state is fresh for every invocation and function call.

while condition { ... } requires a boolean. repeat count { ... } evaluates a nonnegative integer count once. break exits the nearest enclosing loop; continue skips to its next iteration. These keywords are valid only inside loops.

Declare fn name(parameter: integer): integer { ... } between the feature header and command. Parameters and results must declare text, integer, boolean or `list<elementType>` types. Call functions in expressions, for example text(double(3)). Every path must return a matching value with return expression. Functions can call earlier declarations or themselves, but cannot call later declarations or capture command locals. Trailing parameters may declare typed constant defaults, for example fn double(value: integer = 2): integer { return value * 2 }. Required parameters precede defaults. Defaults cannot reference names or call user functions; immutable scalar/list constants are shared safely across fresh frames. Limits are 32 functions, 16 parameters per function and 32 active function calls. Loops, expressions and nested calls share one 8192-step invocation budget and one 32-message output budget.

Save as countdown.aether:

```aether
feature countdown version "1.0.0"
fn label(value: integer): text {
  return "Count " + text(value)
}
command countdown permission "aetherscript.example.countdown" sender any {
  var remaining = 3
  while remaining > 0 {
    send label(remaining)
    set remaining = remaining - 1
  }
  send "Done"
}
```

Test with {"id":"countdown","expectedMessages":["Count 3","Count 2","Count 1","Done"]}. Run /ais run countdown twice; both invocations start at 3.

PersistentVariables provides the JSON host backend; SQLiteVariables provides a separate transactional SQLite backend. Both are core Java services without script-level bindings; var does not persist values or expose player storage. Hosts must select a backend and run storage calls on bounded workers; no automatic migration is performed. Real command registration and this runtime slice do not establish completion of the broader gameplay ecosystem.

## Immutable lists

Lists contain values of one type: `[1, 2, 3]`, `["red", "blue"]` or `[[1], [2]]`. Write an empty list with its element type: `list<integer>()` or `list<list<text>>()`. List types such as `list<integer>` are accepted for function parameters and results. Command arguments still accept only `text`, `integer` and `boolean`.

`values[0]` reads the first element; indices must be integers within bounds. `length(values)` returns an integer. `append(values, value)` returns a new list with a matching element type. Lists are immutable: use `var values = list<integer>()` followed by `set values = append(values, 1)` to replace a local list value. There is no indexed assignment or arbitrary host-array access. Lists contain at most 256 elements each and nest at most eight list types deep.

`==` and `!=` compare matching list types structurally, including nested elements. List concatenation with `+` and `text(listValue)` are rejected. Convert individual scalar elements with `text(value)` when building messages. Feature functions named `length` or `append` take precedence over these built-ins.

`for value in values { ... }` evaluates its list once and visits its elements in order. The loop variable is immutable and scoped to the body; it may shadow an outer name. `break` and `continue` target the nearest loop. Iteration and structural equality share the existing 8192-step invocation budget with expressions and function calls. Lists provide no maps, sets, records, closures or modules.

Save as `scores.aether`:

```aether
feature scores version "1.0.0"
fn total(values: list<integer>): integer {
  var result = 0
  for value in values {
    set result = result + value
  }
  return result
}
command scores permission "aetherscript.example.scores" sender any {
  var values = list<integer>()
  set values = append(values, 1)
  set values = append(values, 2)
  set values = append(values, 3)
  send text(total(values))
}
```

Test with `{"id":"scores","expectedMessages":["6"]}`. Each invocation emits `6` and starts with fresh local state.

## Errors and connection recovery

Read isError and the response body. Validation diagnostics include a location in the message; local validation also returns line, column, path and reason. Correct the source and validate again.
TEXT_SOURCE_REQUIRED means the owner must resolve an existing legacy/duplicate source format. TARGET_DENIED means the requested ID is outside selected permissions.
HTTP 401 invalid_token requires reconnecting with a fresh ais connect browser approval. Superseded, expired, rejected and revoked sessions terminate. HTTP 503 temporarily_unavailable with Retry-After means a valid new connection is waiting for Paper; retry after the indicated delay.
The owner can inspect ais connections and revoke with ais disconnect. Approval does not imply the connection has reached Paper; Connected is confirmed after an actual status response.

## A small beginning. Room to grow.

AetherScript is an open-source Minecraft scripting engine for **Paper 26.3**, with live script reloads and permission-checked behavior. Change a script, reload that feature, and try it immediately.

**0.0.2 adds a safety net:** successful revisions are saved, invalid edits leave your working script running, and diagnostics tell you which file to fix. One editable file. Five saved versions by default.

> [!NOTE]
> This is an experimental, **message-only release**. Write a command in [native AetherScript](https://github.com/MistDig/AetherScript/wiki/AI-Authoring), YAML or JSON. Gameplay events and block health are planned. Scoped remote authoring is opt-in; the server console selects the feature IDs an agent can manage.

        ↓

## The command desk

Use `/ais` in game, or `ais` in console. Script administration requires **`aetherscript.admin`**. Connection management requires the actual server console. Run checks the feature's own permission and sender rule.

| Command | Behavior |
| :--- | :--- |
| `ais connect [feature-ids]` | Server console. Open a browser approval link; optional comma-separated IDs constrain the browser choice. |
| `ais connections` | Server console. List connection IDs, names, permissions and revocations. |
| `ais disconnect [connection-id]` | Server console. Revoke one connection or all connections. Wait for saved confirmation. |
| `/ais status` | Version, readiness, generation, active count, busy state and AI status. |
| `/ais status <feature>` | Running revision, editable path, file state, errors and next action. |
| `/ais list` | Feature running/file states. |
| `/ais validate [feature]` | Check source and command collisions; no activation or saved version. |
| `/ais reload [feature]` | Activate and save valid changed source. |
| `/ais run <feature> [arguments…]` | Invoke with typed positional arguments and permission checks. |
| `/ais history <feature>` | Saved numbers, hashes, timestamps and active marker. |
| `/ais diff <feature>` | Running saved source versus current edit, even if invalid. |
| `/ais rollback <feature>` | Select the closest earlier readable, valid saved revision. |

### Direct script commands

An active feature registers its declared command name, such as `/helloai`, with the same permission, sender rule and argument parser as `/ais run`. A foreign command collision rejects activation and preserves the previous command. Renaming or retiring a feature removes its owned old labels. One command per feature is supported; aliases, subcommands and suggestions remain future work. Client command-tree refresh still needs connected-player evidence.

### One feature or the whole folder?

Targeted reload changes one feature. Full `/ais reload` validates all files and replaces the whole registry; one invalid included file rejects the batch. Removing a source and successfully doing a **full reload** retires the feature. Merely deleting a file before restarting can recover its saved copy.

Unchanged reloads report `UNCHANGED` and add no revision or generation. An explicit full reload releases rollback holds for included features.

| Response | Next step |
| :--- | :--- |
| `VALIDATED` | Reload when ready to activate. |
| `ACTIVE ... saved successfully` | Change activated and committed. |
| `UNCHANGED` | File already matches the working source. |
| `BUSY` | Wait for the current inspection/change, then retry. |
| `NOT_READY` | Check status and console for startup progress/errors. |
| `PERMISSION_DENIED` | Owner must grant the required admin node. |
| `Feature unavailable or permission denied` | Check readiness, ID, feature permission and sender rule. |
| `SAVE_FAILED` / `STORAGE_QUARANTINED` | Inspect storage health and recovery instructions. |

The actual server console can run `ais remote cloud-note` to grant scoped relay management of that feature, and `ais remote-off` to revoke it. `ais remote id1,id2` grants several IDs. Remote mode requires private `relay.json` configuration. The server console can also run `ais pair` to start a read-only status session and `ais unpair` to revoke it. Follow the [pairing guide](https://github.com/MistDig/AetherScript/wiki/Security-and-MCP).

Replies are bounded. Use per-feature commands or console for shortened lists. Hosted MCP supports permission-checked remote validation, source reading, creation/editing, activation and synthetic message tests. The `aether_scripts_apply` tool validates, activates, saves and reads back native source using an expected hash. Selected grants cover exact IDs; full access covers the supported native-script operations across valid feature IDs, including existing .aether files. General console commands, arbitrary filesystem access, Java/plugin installation and broader world operations are outside these grants. See the MCP reference and connection guide.

# Diagnostics-and-Diffs

[☁ Home](https://github.com/MistDig/AetherScript/wiki/Home) · [Start](https://github.com/MistDig/AetherScript/wiki/Getting-Started) · [Commands](https://github.com/MistDig/AetherScript/wiki/Commands) · [Download](https://github.com/MistDig/AetherScript/releases/tag/v0.0.12)

---

## Know what is wrong — and what still runs

An invalid target produces a diagnostic shaped like this; actual line/column depend on your file:

```text
Edit scripts/hello-ai.yml: line 12, column 17; $.commands[0].actions[0].target
Found "everyone". Allowed: sender. Fix: set target to sender; only the invoking sender is permitted
Fix that editable file, then run /ais reload hello-ai.
Rejected; active generation unchanged. Last working scripts remain active.
```

Syntax errors point to the parser location when available. Size/path errors can report `location unavailable`.

### Two states, one edit target

Run `/ais status hello-ai`. It identifies the running saved revision separately from the editable file:

| Label | Meaning |
| :--- | :--- |
| `UP TO DATE` | Editable bytes match running source. |
| `RUNNING SAVED VERSION - file has errors` | Invalid edit; keep fixing the same file. |
| `RUNNING SAVED VERSION - file has unapplied changes` | Valid edit differs from running source. |
| `RUNNING SAVED VERSION - editable file missing` | Restore an editable source while the saved copy runs. |
| `NOT ACTIVE - valid file; reload to activate` | Valid source is not currently active. |
| `DISABLED - file has errors` | No working feature is running for that invalid file. |

### Compare before reloading

`/ais diff hello-ai` gives a compact comparison:

```diff
--- running saved revision #2
+++ scripts/hello-ai.yml (editable, not active)
@@ old line 12, editable line 12 @@
- 12:         target: sender
+ 12:         target: everyone
```

Minus lines are running source; plus lines are your edit. Safely readable invalid files can still be compared. Long changes/lines are shortened for chat; byte-only encoding or line-ending changes get an explanation. This is a comparison, not a patch tool.

Fix the shown file, validate it, reload it, then run the feature. Never edit internal saved copies. If rollback is held, status explains that explicit reload is needed.

## Your first little script

**You need:** Paper 26.3 build 245, Java 25, and console access or `aetherscript.admin`.

### 1 · Install

Download **AetherScript-0.0.12.jar** from the [release](https://github.com/MistDig/AetherScript/releases/tag/v0.0.12). Stop Paper, place it in `plugins/`, and start the server. Keep only one AetherScript plugin JAR installed. The separate MCP JAR does not belong in `plugins/`.

Wait for `Ready. Restored ...`. A fresh install creates and activates `plugins/AetherScript/scripts/hello-ai.yml` automatically.

```text

/ais run hello-ai
```

You should receive `Hello from AetherScript!`. Console commands omit the leading slash.

### 2 · Make it yours

Open `plugins/AetherScript/scripts/hello-ai.yml` and change the final quoted `text` value. Save, then run:

```text
/ais validate hello-ai
/ais reload hello-ai
/ais run hello-ai
```

Validation checks without activating or saving. Reload activates a valid change and saves its revision. There is no automatic file watcher.

For a complete native-language example with variables and a conditional, follow [Writing scripts with AI](https://github.com/MistDig/AetherScript/wiki/AI-Authoring).

### 3 · See what is running

```text
/ais status hello-ai
/ais history hello-ai
/ais diff hello-ai
```

`UP TO DATE` means your editable bytes match the running revision. `RUNNING SAVED VERSION` means the file is missing, invalid or different. Keep editing the file shown by status; the engine manages internal saved copies.

### Permissions

Administration requires `aetherscript.admin`. The example requires `aetherscript.example.hello` to run and defaults to operators. Grant the exact script permission through your permissions system for other players. Invocation is `/ais run hello-ai`; the metadata `name: helloai` does not register `/helloai`.

Stop Paper and back up `plugins/AetherScript/`. Replace the old JAR and restart. **Valid editable scripts now activate automatically at startup.** The first activation creates the initial saved revision; 0.0.1 has no saved history to recover.

A missing configuration is generated. If you previously created a custom config, compare it with [the supported configuration](https://github.com/MistDig/AetherScript/wiki/Revisions-and-Recovery#configuration); unknown keys are rejected. # Language-Reference

## Text scripts and structured definitions

AetherScript accepts **`.aether`, YAML and JSON** sources. They share the immutable message model, permission checks, validation, saved revisions and recovery behavior.

Save one file per feature as `scripts/<id>.aether`, `.yml`, `.yaml` or `.json`. Its filename and feature ID must match. Remove the other example format before installing a different one for the same ID.

## Your first text script

Save this as `scripts/hello-ai.aether`:

```text
feature hello-ai version "1.0.0"
command helloai permission "aetherscript.example.hello" sender any {
  let greeting = "Hello"
  let count = 2 + 3
  if count == 5 {
    send greeting + " from AetherScript!"
  } else {
    send "Unexpected count"
  }
}
```

```text
/ais validate hello-ai
/ais reload hello-ai
/ais run hello-ai
```

The result is `Hello from AetherScript!`. Values and conditions evaluate during preparation at validation/reload, and their selected messages are stored in the compiled feature. Every invocation then applies the feature's permission, sender and active-generation checks.

The `command` header registers a real Paper command name. Direct console invocation, replacement and restart are tested. Connected-player command-tree visibility remains unverified; `/ais run <id>` is also available.

## Command arguments in 0.0.7

Save this as `scripts/greet.aether`, validate it and reload it as an administrator.

```aether
feature greet version "1.0.0"
command greet permission "aetherscript.example.greet" sender any {
  arg name: text
  arg count: integer = 1
  arg excited: boolean = true
  if excited {
    send "Hello " + name + "!"
  } else {
    send "Hello " + name
  }
  if count > 1 {
    send "Repeat count: " + text(count)
  }
}
```

Run `/ais run greet MistDig` to receive `Hello MistDig!`. Run `/ais run greet Alex` to receive `Hello Alex!` from the same active script. For a name containing spaces, use `/ais run greet "Alex Smith"`.

Run `/ais run greet Alex 2 false` to receive `Hello Alex` and `Repeat count: 2`. An integer is a signed 64-bit decimal value. A boolean is `true` or `false`.

Declare arguments before other statements. Required arguments precede defaults. Types are `text`, `integer` and `boolean`. There are at most 16 positional arguments. Missing, extra and mistyped arguments produce an error and usage example before messages are delivered. An unclosed quote reports how to close it.

Argument-dependent calculations and conditions execute per invocation. Both branches are checked on validation. Legacy scripts using only `let`, `if` and `send` without arguments preserve their preparation behavior and semantic hashes. A `var`/`set`, loop or function declaration selects invocation-time evaluation even without arguments.

The following deliberately invalid script has a text default for an integer argument.

```aether-invalid
feature bad-default version "1.0.0"
command bad-default permission "aetherscript.example.bad" sender any {
  arg count: integer = "many"
  send text(count)
}
```

### Values and scope

| Form | Meaning |
| --- | --- |
| `let count = 2 + 3` | An immutable local integer. |
| `var count = 3` | A mutable local value, fresh for each invocation. |
| `set count = count - 1` | Update the nearest visible mutable binding with a matching type. |
| `let greeting = "Hello"` | An immutable local text value. |
| `let ready = count == 5` | An immutable local boolean. |
| `send greeting + "!"` | Append a plain message to the selected compiled output. |
| `if ready { ... } else { ... }` | Select a branch during preparation, or per invocation in commands declaring arguments or runtime control constructs. |
| `text(count)` | Explicitly convert an integer, boolean or text value to text. |

Locals are lexically scoped. An inner block may shadow an outer name. Duplicate declarations in the same block fail. An initializer can refer to earlier bindings. Names are ASCII letters/digits/underscores, beginning with a letter or underscore; reserved statement/value keywords cannot be local names.

### Operators

| Operators | Types and behavior |
| --- | --- |
| `+` | Add two integers or concatenate two text values. Use `text(...)` for mixed text/integer/boolean output. |
| `-`, `*`, `/`, `%` | Integer arithmetic. Division truncates toward zero and remainder keeps the dividend's sign. |
| `==`, `!=` | Equality between matching types; lists compare structurally. |
| `<`, `<=`, `>`, `>=` | Integer comparisons. |
| `!`, `&&`, `||` | Boolean negation, conjunction and disjunction. |
| `(...)` | Explicit grouping. |

Precedence from lowest to highest is `||`, `&&`, equality, integer comparison, addition/subtraction, multiplication/division/remainder, then unary operators. Integer operations reject signed 64-bit overflow. Evaluated division/remainder by zero fails. `&&` and `||` short-circuit evaluation, while both operands still receive static type checking.

Both branch bodies are parsed and type-checked before activation. An undefined name or mismatched type in an inactive branch rejects the source. Only the selected branch evaluates and contributes messages.

### Source and bounds

Statements end at a newline or at their closing-block boundary. `//` begins a comment. Text uses double quotes and supports escaped quotes, backslashes, newline, carriage return and tab. Emitted message text must satisfy the existing plain-text/control-character rules.

Source is strict UTF-8 with an optional leading BOM. Diagnostics identify the source line and column. The initial limits are 64 KiB source, 8,192 tokens, 2,048 expression nodes, 256 statements, nesting depth 32 and 8,192 preparation steps. The selected program must emit 1–32 nonempty plain messages, each at most 2,048 UTF-16 units.


## Mutable locals, loops and typed functions

var count = 3 declares an inferred mutable local. set count = count - 1 updates the nearest visible mutable binding with the same type. let, arguments and function parameters remain immutable. Locals support text, integer, boolean and homogeneous lists; state is fresh for every invocation and function call.

while condition { ... } requires a boolean. repeat count { ... } evaluates a nonnegative integer count once. break exits the nearest enclosing loop; continue skips to its next iteration. These keywords are valid only inside loops.

Declare fn name(parameter: integer): integer { ... } between the feature header and command. Parameters and results must declare text, integer, boolean or `list<elementType>` types. Call functions in expressions, for example text(double(3)). Every path must return a matching value with return expression. Functions can call earlier declarations or themselves, but cannot call later declarations or capture command locals. Trailing parameters may declare typed constant defaults, for example fn double(value: integer = 2): integer { return value * 2 }. Required parameters precede defaults. Defaults cannot reference names or call user functions; immutable scalar/list constants are shared safely across fresh frames. Limits are 32 functions, 16 parameters per function and 32 active function calls. Loops, expressions and nested calls share one 8192-step invocation budget and one 32-message output budget.

Save as countdown.aether:

```aether
feature countdown version "1.0.0"
fn label(value: integer): text {
  return "Count " + text(value)
}
command countdown permission "aetherscript.example.countdown" sender any {
  var remaining = 3
  while remaining > 0 {
    send label(remaining)
    set remaining = remaining - 1
  }
  send "Done"
}
```

This example emits its lines immediately; loops do not delay server ticks. Timed scheduling is a separate milestone.

Test with {"id":"countdown","expectedMessages":["Count 3","Count 2","Count 1","Done"]}. Run /ais run countdown twice; both invocations start at 3.

PersistentVariables provides the JSON host backend; SQLiteVariables provides a separate transactional SQLite backend. Both are core Java services without script-level bindings; var does not persist values or expose player storage. Hosts must select a backend and run storage calls on bounded workers; no automatic migration is performed. Native metadata registration and this runtime slice do not establish completion of the broader gameplay ecosystem.

## Immutable lists

Lists contain values of one type: `[1, 2, 3]`, `["red", "blue"]` or `[[1], [2]]`. Write an empty list with its element type: `list<integer>()` or `list<list<text>>()`. List types such as `list<integer>` are accepted for function parameters and results. Command arguments still accept only `text`, `integer` and `boolean`.

`values[0]` reads the first element; indices must be integers within bounds. `length(values)` returns an integer. `append(values, value)` returns a new list with a matching element type. Lists are immutable: use `var values = list<integer>()` followed by `set values = append(values, 1)` to replace a local list value. There is no indexed assignment or arbitrary host-array access. Lists contain at most 256 elements each and nest at most eight list types deep.

`==` and `!=` compare matching list types structurally, including nested elements. List concatenation with `+` and `text(listValue)` are rejected. Convert individual scalar elements with `text(value)` when building messages. Feature functions named `length` or `append` take precedence over these built-ins.

`for value in values { ... }` evaluates its list once and visits its elements in order. The loop variable is immutable and scoped to the body; it may shadow an outer name. `break` and `continue` target the nearest loop. Iteration and structural equality share the existing 8192-step invocation budget with expressions and function calls. Lists provide no maps, sets, records, closures or modules.

Save as `scores.aether`:

```aether
feature scores version "1.0.0"
fn total(values: list<integer>): integer {
  var result = 0
  for value in values {
    set result = result + value
  }
  return result
}
command scores permission "aetherscript.example.scores" sender any {
  var values = list<integer>()
  set values = append(values, 1)
  set values = append(values, 2)
  set values = append(values, 3)
  send text(total(values))
}
```

Test with `{"id":"scores","expectedMessages":["6"]}`. Each invocation emits `6` and starts with fresh local state.

## YAML and JSON

Structured definitions continue to use schema version 1:

```yaml
schemaVersion: 1
id: hello-ai
version: "1.0.0"
requires:
  - runtime.message.send
commands:
  - name: helloai
    permission: aetherscript.example.hello
    sender: any
    actions:
      - type: message.send
        target: sender
        text: "Hello from AetherScript!"
```

| Field | Accepted meaning |
| --- | --- |
| `schemaVersion` | Integer `1`. |
| `id` | 1–64 characters, beginning with a lowercase letter followed by lowercase letters, digits or hyphens. Matches the filename. |
| `version` | Required nonempty label up to 64 characters, independent of saved revision numbers. |
| `requires` | Exactly `[runtime.message.send]`. The text frontend infers this requirement. |
| `commands` | Exactly one command definition. |
| `name` | Same character rules as feature ID; unique among active features. Used by the dispatcher and Paper native command metadata registration; client command-tree visibility remains unverified. |
| `permission` | Explicit dotted permission node up to 128 characters, with wildcard characters rejected. |
| `sender` | `any` or `player`. The latter restricts invocation to players. |
| `actions` | 1–32 message actions. |
| `type` | `message.send`. |
| `target` | `sender`, meaning the invoker. |
| `text` | Nonempty plain text up to 2,048 UTF-16 units, with control characters and legacy section-sign formatting rejected. |

Unknown fields/actions, duplicate keys, multiple documents, YAML tags, anchors and aliases are rejected. Quote string values. JSON requires quoted keys and valid commas. YAML/JSON values are literal definitions; the textual expression grammar belongs to `.aether` sources.

The engine caps active features at 128, tracked histories at 128 and scripts-directory entries at 256. Files must be regular files inside the owner-managed scripts directory.

## Available tools

Start with `aether_server_status` to confirm which server is connected. A selected-script connection can access only its approved feature IDs. A full-access connection can create and edit any valid native .aether feature ID, including existing scripts.

| Tool | Input | Result and next step |
| --- | --- | --- |
| `aether_server_status` | No arguments | Current live registry generation and server grant. A connection failure is an error. |
| `aether_scripts_list` | No arguments | Selected IDs, or existing native IDs under full access. Full access can create new valid IDs. |
| `aether_scripts_read` | `id` | Editable source, source hash, active hash, revision and generation. Read before editing. |
| `aether_scripts_validate` | `id`, `source` | Validates a complete native script using the server compiler. |
| `aether_scripts_apply` | `id`, `source`, `expectedHash` | Validates, activates, saves and reads back the result. Use the read hash, or `ABSENT` to create. |
| `aether_scripts_test` | `id`, `expectedMessages`, optional `arguments` | Invokes the active feature using a synthetic sender, captures messages and checks exact equality. |

The separate local gateway also exposes `aether_capabilities`, `aether_validate`, and `aether_test`. These can validate and test supplied source offline. Offline success does not imply server authorization.

## A reliable editing workflow

Read the feature and retain its hash. Validate the complete replacement. Apply with that exact hash. Read the feature again and check that the source and active hashes match the intended change. Run a test with the expected messages and report the actual messages and comparison result.

On a stale-hash error, read again before deciding whether to merge the owner's edit. On timeout or network failure, read back first because the operation may have completed. A successful request can be followed by a failure delivering its reply.

## Test limitations

Synthetic tests capture message actions. They do not impersonate a connected player or verify client rendering. A player-only sender rule requires a player test. Test mismatch means the actual messages differ from the expected list, even when invocation completed.

## Boundaries and diagnostics

An unknown ID outside the grant is denied. A malformed or invalid source cannot replace a saved working revision. Use `ais status <id>`, `ais diff <id>`, `ais history <id>` and rollback on the server when investigating a failed update.

The hosted service bounds JSON requests, source size, pending operations and daily work. Keep native sources below the tool schema's source limit. The local compiler supports larger sources, but a transport envelope includes JSON escaping and metadata.

# Performance

[☁ Home](https://github.com/MistDig/AetherScript/wiki/Home) · [Start](https://github.com/MistDig/AetherScript/wiki/Getting-Started) · [Commands](https://github.com/MistDig/AetherScript/wiki/Commands) · [Download](https://github.com/MistDig/AetherScript/releases/tag/v0.0.12)

---

## Fast means measured, bounded work

AetherScript shares Paper's JVM garbage collector. It cannot remove GC selectively and does not force collection or change server GC flags.

- Parsing/compilation happens at startup, validation and reload, not each invocation.
- Source reads, revision writes and audit flushes use a bounded worker.
- Immutable registry swaps and message delivery run on Paper's main thread.
- Actions, source size, histories, directory entries and queues are bounded.
- There is no per-tick script polling loop or automatic watcher.

Messages still allocate components, and reload creates objects. GC-free, zero-allocation or zero-lag claims would be inaccurate.

### Will recovery make startup heavy?

Editable files already need reading and validation. Recovery adds bounded metadata inspection and saved-source reads when needed, rather than loading every historical version. It runs in the background; readiness waits for preparation. Default history is five versions and active features are capped at 128. Large-server startup latency has not been benchmarked.

### How Rust differs

Rust normally releases owned memory deterministically without a tracing collector. That can offer memory-lifetime control, but does not automatically make every program faster. A Rust component would not remove Paper's Java GC and would add a native integration boundary.

The immediate work is keeping invocation small and profiling realistic workloads: allocations, retained heap, GC pauses, invocation latency and p95/p99 tick time. The 100-reload test is a behavior test, not a leak or TPS benchmark.

## One file to edit. A safety net behind it.

Edit `plugins/AetherScript/scripts/<feature>.yml` (or `.aether`, `.yaml`, `.json`). The engine manages internal working copies under `storage/`; do not edit those copies.

### What is saved?

Successfully activated **changed source** creates a numbered revision. Invalid edits, validation-only commands and unchanged reloads consume no history. Comment/whitespace byte changes count as changes. The script's `version` label does not control revision numbers.

Default: **five saved revisions per feature, including the active one**. The oldest non-active revision is removed when the limit is exceeded. Numbers keep increasing. Repeated content can share one stored blob across historical revisions.

### On startup

| Situation | Result |
| :--- | :--- |
| Valid editable source; no rollback hold | Activate it, saving a revision if changed. |
| Invalid/missing file with usable saved source | Run saved source and explain the edit target. |
| Invalid new feature, no history | Disable that feature; unrelated valid sources can load. |
| Corrupt active bytes and unusable editable file | Try earlier committed, checksum-valid, supported revisions. |
| No usable saved copy | Disable the affected feature and report it. |
| Corrupt manifest | Block engine startup; never guess from loose blobs. |
| Rollback held | Restore the selected revision until explicit reload. |

Recovered scripts are parsed and validated against the current policy. Startup I/O runs on the worker, but readiness waits for preparation. Recovery does not activate every historical revision; corrupt copies may require checking earlier ones. No instant-start or large-server performance claim is made.

### Roll back without losing edits

```text
/ais history hello-ai
/ais rollback hello-ai
/ais status hello-ai
/ais diff hello-ai
```

Rollback selects the closest earlier readable, valid revision. Repeating walks backward through retained history. It creates no revision and **does not overwrite the editable file**.

The selected rollback persists across restarts. Fix the editable file and run `/ais reload hello-ai` to opt back in. A successful full reload also releases holds for included features. Rollback cannot undo messages already sent or world/economy effects.

### Configuration

`plugins/AetherScript/config.yml`:

```yaml
configVersion: 1
retainVersions: 5
```

Allowed retention: **1–50**, applied on restart. A limit of 1 leaves no earlier revision. Lowering it protects the active version, even an older rollback. Unknown/duplicate keys and anchors are rejected.

### Interrupted saves and storage failures

Source bytes are staged before a checksummed manifest is atomically replaced. Only manifest-referenced revisions are committed. Pending files and orphan blobs are not selected at startup. Abrupt-process-exit tests cover boundaries before replacement and after commit.

This is not a power-loss durability guarantee: filesystem directory flushing varies, particularly on Windows. Atomic moves are required; the store does not silently substitute a non-atomic replacement.

If saving or the completion audit fails after activation, the engine attempts to restore the old durable state and registry. Registry restoration uses a new generation. If restoration is uncertain, operations are quarantined. Already dispatched effects cannot be undone.

> [!IMPORTANT]
> Back up the whole `plugins/AetherScript/` directory with Paper stopped. For `STORAGE_CORRUPT` or `STORAGE_QUARANTINED`, stop Paper, preserve the damaged directory for diagnosis and restore a known-good owner backup. Do not randomly delete manifests or edit hashes. Revision storage complements backups; it does not replace them.

## Grow the language one tested surface at a time

Published versions start at 0.0.1. The original v0.1–v0.5 roadmap labels describe engineering milestones, not automatic patch numbers. Planned features are not valid syntax today.

### Available now

Native message commands support typed arguments, mutable scalar locals, bounded loops and typed functions at invocation time. Legacy commands without arguments or advanced constructs retain preparation-time evaluation. Real owned command names are registered; connected-player command-tree refresh and suggestions remain unverified. Live reload, saved revisions, startup recovery, diagnostics, diff, history and rollback are available. Hosted OAuth MCP can read, validate, apply and test native scripts under selected or full native-script grants. Events and the ten-heart block remain planned.

### Next · reusable gameplay primitives

The block-health idea needs block-break events, location-scoped state, controlled damage/cancellation and displays with cleanup. Build these as reusable primitives, not one hard-coded demo. Design for individual locations, material filters, regions and all-block scopes. Check protection-plugin interoperability, unloaded chunks, replacement/explosion handling, concurrent players, reload/restart behavior and resource limits.

| Area | Design and verification work |
| :--- | :--- |
| Human DSL/editor tools | Same typed IR, source maps, versioned grammar, useful errors and bounded execution. |
| Events/timers | Allowlisted events, correct threading, generation-aware cancellation and cleanup. |
| Cooldowns | Player/feature scope, clock semantics, restart policy and bounded state. |
| Scoreboards | Ownership, other-plugin coexistence, cleanup and update budgets. |
| Boss bars | Player visibility, lifecycle ownership, bounded updates and cleanup. |
| GUIs | Inventory identity, click/drag checks and stale-session invalidation. |
| Custom items | Server-owned identity/PDC, allowlisted components/recipes and duplication/transfer tests. |
| Persistent player data | Typed schemas, atomic updates, migrations, backups and privacy/retention. |
| Economy | Currency precision, idempotent transfers, atomic balances, permissions and double-spend tests. |
| Quests | Bounded state machines, persistent progress, deduplicated events/rewards and safe migrations. |

### Secure deployment and connectivity

First implement server-side capability policy, scoped principals, authenticated loopback access, revocation, quotas, bound approvals and crash-safe transactions. Local revisions are one piece, not completion of the remote security milestone.

Personal-relay authoring was introduced in 0.0.6, shared hosted OAuth in 0.0.7, and explicit full/selected native-script grants in 0.0.8. The separate loopback pairing remains status-only. Broader gameplay authority and per-edit approvals remain future work. Verify client reconnects, timeouts, unknown results and named clients.

Remote servers need owner-provisioned identities, TLS/mTLS or a reviewed private tunnel, expiring scoped credentials, rotation/revocation and replay defenses. Test impersonation, compromised gateways, partitions, retries and lost acknowledgements. A tunnel does not replace application authorization.

Performance measurements and connected-player checks remain release gates. Purpur needs independent tests; Folia is outside the current claim.

## Connect your AI

Install AetherScript 0.0.8 in the Minecraft server's plugins folder and start the server. Java 25 is required. Keep one plugin JAR installed.

### On the Minecraft computer

In the actual server console, type `ais connect`. Open the private link it prints on the computer where you use your AI app. The link expires in ten minutes and works once. Keep console logs and the link private.

The plugin creates its own identity automatically. The shared AetherScript service handles browser approval. You can use PCs on different networks.

### On the AI computer

Choose your AI app on the page. Follow its setup instructions and use the same browser for its authorization screen.

For Codex on Windows, download the linked ZIP, extract it, and double-click `Connect-AetherScript.cmd`. It registers the hosted server and opens Codex sign-in. Java and a separate MCP JAR are unnecessary for this hosted connection.

For ChatGPT or Claude, add the displayed hosted MCP address in your app's custom connector settings and begin authorization. Availability depends on your account and workspace settings. For Cursor use the installation link. Claude Code and Cline can use the hosted OAuth address if the installed client supports it. Their actual client verification is recorded in the [matrix](https://github.com/MistDig/AetherScript/blob/v0.0.8/docs/mcp-clients.md).

### Approve and check

On the authorization page, confirm the server name and callback destination. Choose a connection name. The default Create and edit all AetherScript scripts option grants creation and editing of every native .aether feature, including existing files. Choose Only selected scripts to restrict the connection to IDs such as `cloud-note`. Approve the listed operations. Existing restricted connections stay restricted until you explicitly create a new approval. Console-restricted IDs cannot be expanded by the browser.

Ask your AI to check AetherScript server status. The pairing page shows Connected after Paper answers that client's request. Approval alone shows a waiting state.

Ask the AI to create `cloud-note`, activate it and test its actual output. It can access all native script IDs or the selected IDs according to the approval. Script tests capture messages from a synthetic sender. Player-only scripts require a player test.

### Manage access

In the server console, `ais connections` lists each connection ID, name and full or selected access. Full access includes existing .aether files. YAML/JSON sources require owner conversion before remote editing and are protected from accidental replacement. Connections survive normal restarts.

Use `ais disconnect <connection-id>` for one app or `ais disconnect` for all apps. Access blocks immediately. Wait for the console's saved-revocation confirmation before restarting.

Connections expire after 30 days. Run `ais connect` again to authorize a fresh connection. Local scripts continue working during a relay outage.

## Privacy and limits

The service uses HTTPS and sees script source and results. Keep `plugins/AetherScript/connections.json` private. It contains the server credential and local grants. Copying it clones the server identity. Each new installation should generate its own file.

The public service bounds enrollment, app registration, connections, daily operations and payload sizes. It runs on a free Cloudflare account, so quota exhaustion can temporarily interrupt remote access. A failed or timed-out apply may have completed. Read the source and active hash before retrying.

Script edits use an expected source hash. A stale or invalid edit is rejected. Revisions and restart recovery remain available. Grants authorize the fixed script operations listed on the page.

## Existing installations

The 0.0.6 personal relay and 0.0.5 loopback status workflows remain available. Their private files are unnecessary for `ais connect`. Use the new browser flow explicitly when migrating.

## Gemini and manual OAuth credentials

Choose Gemini on the pairing page. Automatic client registration supports HTTPS web callbacks and OAuth clients using a secret. If the app asks for a Client ID and Client Secret, use the page's manual registration section. Enter the callback URL shown by the app, select its authentication method and register that individual client. Save the returned credentials only in that app. Secrets are displayed once and should stay out of chat and screenshots.

The server publishes OAuth discovery and a /register endpoint. Public clients use S256 PKCE without a secret; confidential clients can use client_secret_basic or client_secret_post with S256 PKCE. Existing public-client registrations remain compatible. Actual Gemini app testing is recorded separately from protocol tests.

## An old connection keeps waiting

Running `ais connect` again supersedes the previous uncompleted link and approval. Completed active connections keep their permissions. Superseded, rejected, expired and revoked tokens return a terminal invalid_token authentication response. Reconnect or sign in again using a fresh console link. If the client caches an old token, disconnect and reconnect AetherScript in that app.

During a valid handshake, the browser creates an approval, Paper saves the grant on its next poll, Paper acknowledges it, and the AI app reads live status. A short wait before the next poll is expected. A rejected grant is logged once per changed state and reported to the relay.

# Troubleshooting

[Home](https://github.com/MistDig/AetherScript/wiki/Home)

---

## The plugin did not start

On the Minecraft computer, use the server console and type `ais status`. Confirm the installed version, `ready=true`, and the startup log. Use Java 25 and Paper 26.3. Keep one AetherScript plugin JAR in plugins. Keep the existing AetherScript folder when upgrading.

If storage is corrupt, preserve the files and consult the recovery guide before editing internal storage. Local script errors identify the editable source path and preserve the saved working version.

## Permission denied in Minecraft

Administrative commands require `aetherscript.admin`. It defaults to operators. A permissions plugin can override the default. Use the server console to check status and grant the intended node through your permissions system.

The feature's own permission is checked separately when running it. Browser approval belongs in the actual server console through `ais connect`.

## My pairing link expired

On the Minecraft computer, type `ais connect` again. Open the fresh link on the AI computer. Use the same browser for the AI app's authorization. Each console link authorizes one connection and expires after ten minutes.

Do not share the link or paste it into an AI conversation. A previously consumed link cannot be reused.

## The page says waiting

Approve the exact feature IDs and finish the AI app's sign-in. Ask the app to check AetherScript server status. Connected appears after that app's request reaches Paper and Paper answers.

If Paper is offline, start it and allow the connection to retry. Check the server console for a relay-unavailable message. Daily free-service quotas can temporarily interrupt access. Local scripts still run.

## My AI cannot see a script

Use `ais connections` in the Minecraft console and check its exact IDs. Creating a new feature requires full access or approving that ID. A connection cannot enlarge its own grant. Full access is available only through a fresh owner approval. Use a fresh `ais connect` approval for a new grant.

The native file's ID must match its filename. Keep one source format per feature ID. A remotely managed native feature cannot overwrite an existing YAML feature of the same ID.

## A test failed

Read the actual message list. Compare spelling, case, punctuation and order. A synthetic sender cannot run player-only features. Run player behavior in Minecraft with the correct permission.

## I want to remove access

On the Minecraft computer, type `ais disconnect` for all connections, or include one ID from `ais connections`. Access blocks immediately. Wait for the console to confirm saved revocation before restarting. Your scripts keep running locally.
